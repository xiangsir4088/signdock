## 1. 简介

SignDock 是一个 **Windows 托盘常驻小工具**（Tauri 2 + Rust 编写），每日按你设定的时间自动领取本机关注的四款开发者产品的免费额度：

| 产品 | 厂商 | 领取内容 |
|---|---|---|
| **WorkBuddy** | 腾讯 | AI 助手免费额度（积分） |
| **Trae** | 字节跳动 | AI 编程助手免费额度 |
| **Qoder** | Qoder 官方 | 每日 100 秒点（北京时间 10:00 刷新） |
| **秒哒** | 百度 | 每日 100 秒点（登录即送，无领取接口） |

### 设计原则

1. **凭证零输入**。SignDock 从不要求你粘贴 token。四款产品的凭证要么读本机登录态，要么走官方 OAuth，要么由 SignDock 自己的登录窗口封存，全程不经过键盘输入。
2. **单用户、单账号、单机**。不提供多账号、多开、批量签到、账号切换、会话复制。这类需求超出「个人自动化」范围，本项目不支持。
3. **只做当前账号的自动化**。任何可能导致厂商风控的信号都会立即停止（触发后请立即停用，见 [§11](#11-已知限制与厂商风险)）。
4. **厂商独立**。SignDock 是第三方项目，与 WorkBuddy（腾讯）、Trae（字节跳动）、Qoder、秒哒（百度）**无任何关联或背书**。相关商标归各自权利人所有。

### 你会得到什么

- 到点自动签到，不用每天手动去几个网站点几个页面
- 结果通过系统通知送到桌面（成功/失败/需人工）
- 历史签到记录保存在本地 SQLite，随时可查
- 每款产品独立开关、独立时间、独立重试策略
- 全部配置本地保存，不联网上传

## 2. 安装

### 2.1 下载绿色版（推荐）

从 GitHub Release 页面下载：

```
SignDock-portable-0.1.0-windows-x64.zip  （约 4.3 MB）
```

**安装步骤：**

1. 把 zip 解压到任意目录，推荐 `D:\SignDock\` 或 `C:\Users\<你的用户名>\SignDock\`
2. 解压后进入 `SignDock/` 目录，双击 `SignDock.exe`
3. 首次启动会弹出一个设置窗口和系统托盘图标，说明启动成功

**绿色版的优点：**

- 免安装，不用跑安装程序、不用管理员权限
- 关闭 = 直接结束进程（托盘右键"退出"），不留残留
- 想迁移就把整个文件夹拷到 U 盘，另一台电脑解压即用

**绿色版的限制：**

- 首次运行需要联网下载微软 WebView2 Runtime（Win10 2004+ / Win11 都内置，一般不用管）
- 没有开始菜单快捷方式（可自行右键 `SignDock.exe` → 发送到 → 桌面快捷方式）

### 2.2 从源码构建（开发者用）

前置工具：
- [Rust](https://rustup.rs/)（稳定版）
- [Node.js](https://nodejs.org/) 22+
- [Tauri 2 prerequisites](https://tauri.app/start/prerequisites/)（Windows 需要安装 Visual Studio Build Tools 和 WebView2）

```bash
git clone https://github.com/<owner>/signdock.git
cd signdock
npm install                 # 前端依赖（Vite + TypeScript）
npm run tauri build         # 打包安装包
```

产物在 `src-tauri/target/release/bundle/msi/` 下（默认构建安装版）。

### 2.3 系统要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 2004 (Build 19041+) 或 Windows 11 |
| WebView2 Runtime | Win10 2004+ / Win11 已内置，Win10 更早版本需手动安装 |
| 磁盘空间 | 绿色版解压后约 40 MB |
| 内存占用 | 常驻约 60-80 MB |

## 3. 快速上手：5 分钟跑通

### Step 1：启动 SignDock

双击 `SignDock.exe`。你会看到：

- **系统托盘图标**（屏幕右下角）：一个绿色圆点，代表 SignDock 正在运行
- **设置窗口**：默认 800×600，标题栏显示"SignDock 设置"

### Step 2：熟悉界面

打开的设置窗口长这样（顶部）：

```
● SignDock                    本机 AI 工具自动签到 · 托盘常驻

┌─[ WorkBuddy ]─[ Trae ]─[ Qoder ]─[ 秒哒 ]─┐  ← 产品 Tab，切换要配置的产品
│                                              │
│  ● WorkBuddy                     今天已签 ✓  │  ← 卡片标题 + 今日状态徽章
│                                              │
│  模式：自动签到 ▾     时间：09:00             │
│  重试次数：2    间隔分钟：5                   │
│                                              │
│  登录账号：（读取本机登录态…）                │
│                                              │
│  余额       今日消耗   今日到期   明日过期     │
│  12.34      0.50       1.00       0.00       │
│                                              │
│  [ 保存 ]  [ 立即执行一次 ]  [ 刷新积分 ]      │
│                                              │
│  点上方「登录并获取 token」，在弹出的官方登录  │
```

**关键元素速览：**

| 元素 | 位置 | 作用 |
|---|---|---|
| **产品 Tab** | 顶部（分段控制） | 切换要配置的产品 |
| **状态点** | Tab 左边小圆点 | 颜色指示状态：绿=成功 / 黄=提醒 / 红=失败 / 灰=未执行 |

| **时间输入** | 模式右侧 | 每日触发时刻（HH:MM），默认 09:00 |
| **保存按钮** | 卡片底部左侧 | 把模式/时间/重试配置写入本地数据库 |
| **立即执行一次** | 保存按钮右侧 | 立刻跑一次签到，不用等到点 |
| **刷新积分** | 最右 | 手动刷新余额显示 |
| **登录并获取 token** | 按钮下方 | 只对 WorkBuddy 和秒哒出现，其他产品不需要 |
| **签到日志** | 卡片底部表格 | 最近 5 条执行记录 |

### Step 3：配置第一个产品（建议从 Trae 开始，最简单）

**理由：** Trae 完全自动读本机登录态，不需要任何 OAuth 或额外登录动作。只要你的电脑已经装过并登录过 Trae，SignDock 就能直接读。

1. 点击顶部 **Trae** Tab
2. 模式选 **自动签到**
3. 时间默认 **09:00**（或改成你习惯的时间）
4. 点 **保存**
5. 点 **立即执行一次** — 应该会看到"签到成功：xxx"或"今日已签到，没有重复领取。"

### Step 4：配置其他产品

依次点击 Qoder → WorkBuddy → 秒哒 Tab，按 [§5](#5-四个产品的凭证配置) 的说明分别配置。

## 4. 每日使用

### 4.1 日常流程

**正常的一天（配置好之后）：**

1. 早上开机、开机自启 SignDock（见 §4.3）
2. 到设定时间，SignDock 自动在后台签到
3. 桌面弹出系统通知："SignDock：WorkBuddy 签到成功，+50 积分"
4. 不用打开设置窗口，不用做任何操作

**如果某天签到失败：**

1. 收到失败通知："SignDock：WorkBuddy 签到失败，需人工处理"
2. 点击托盘图标 → "打开设置"
3. 看该产品卡片的最近日志，找到失败的详情
4. 按 [§9 故障排查](#9-故障排查-faq) 处理

### 4.2 手动触发签到

任何时候都可以点 **"立即执行一次"** 按钮立刻签到，不用等到点。常见场景：

- 刚登录完一个产品，想立刻验证 SignDock 能读到你的账号
- 早上开机，今天还没到签到时间，想提前签到
- 昨天失败了，今天想手动补签

**注意：** 一个产品一天只能签一次。已经在自动签到或已手动签过后，再点"立即执行一次"会显示"今日已签到，没有重复领取。"

### 4.3 开机自启

SignDock 默认**不**开机自启。如果你希望每次开机都跑：

1. 打开 **任务管理器** → **启动** 选项卡
2. 点 **右键 → 打开任务管理器 → 启动应用设置**
3. 在文件夹里点右键"新建" → 快捷方式
4. 目标填：`"C:\路径\SignDock\SignDock.exe"`（引号必填，路径有中文/空格时必须）
5. 把快捷方式拖到 `shell:startup` 快捷目录（Win+R → 输入 `shell:startup`）

**或者更简单：** 右键 SignDock 目录下的快捷方式 → 发送到 → 启动菜单。

### 4.4 完全退出

托盘图标右键 → **退出**。SignDock 是单实例，退出后再双击 exe 会重新启动。

## 5. 四个产品的凭证配置

每款产品的凭证获取方式不同。下面按配置难度从易到难排。

### 5.1 Trae（最简单，零操作）

**前置：** 你的电脑上已经安装并登录过 [Trae](https://www.trae.ai/) IDE。

**配置步骤：**

1. 点击顶部 **Trae** Tab
2. 模式选 **自动签到**
3. 时间设 **10:00**（Trae 每日额度北京时间 10:00 刷新，设在这之后）
4. 点 **保存**

**SignDock 做了什么：** 直接读你本机 Trae 安装目录下的登录态文件（只读，不修改）。

**如果失败：**
- 打开 Trae 应用让它自己刷新一次 token
- 回到 SignDock 点 **立即执行一次** 试试
- 还不行看 [FAQ §9.4](#94-trae-签到失败token-过期)

### 5.2 Qoder（零操作，但要注意时间窗口）

**前置：** 你的电脑上已经安装并登录过 [Qoder](https://qoder.com/)。

**配置步骤：**

1. 点击 **Qoder** Tab
2. 模式选 **自动签到**
3. **时间必须设在 10:00 之后**（例如 10:05 或 10:30）— Qoder 每日 100 秒点是北京时间 10:00 刷新，10:00 之前签不到
4. 点 **保存**

**SignDock 做了什么：** 只读解密 Qoder 的登录凭据文件，**不回写**（不会改你的本地登录状态）。

**如果 10:00 前看到"今日窗口未开"：**
- 这是正常的！状态是 `windowPending`（黄色）
- SignDock 会按你设定的重试间隔（默认 5 分钟）回头复查
- 到 10:00 后会自动重试，通常不用手动干预
- 但如果 10:00 后仍然失败，看 [FAQ §9.5](#95-qoder-1000-后仍显示窗口未开)

### 5.3 WorkBuddy（走一次 OAuth）

**前置：** 你需要有一个 WorkBuddy 账号（登录 [workbuddy.cn](https://www.workbuddy.cn/) 一次即可，SignDock 会跳自己的官方登录页）。

**配置步骤：**

1. 点击 **WorkBuddy** Tab
2. 模式选 **自动签到**
3. 时间设 **09:00**（或你喜欢的时间）
4. 点 **保存**
5. 滚动到卡片下方，点 **[登录并获取 token]** 按钮
6. 系统浏览器会自动打开 WorkBuddy 官方登录页 → 用你的账号登录一次
7. 登录成功后，SignDock 会自动收到通知，状态栏显示"登录成功：xxx。现在可直接点「立即执行一次」"
8. 点 **立即执行一次** 验证

**SignDock 做了什么：**
- 借用你系统浏览器的官方登录页（不需要你复制粘贴任何 token）
- 登录成功后，SignDock 拿到的 access_token / refresh_token 用 **DPAPI（Windows 数据保护 API）** 加密后存在 `%APPDATA%\com.signdock.app\workbuddy-cred.json`
- refresh_token 会在 access_token 过期时自动续期，不用重新登录
- 换用户或换机器，DPAPI 解不开，需要重新登录一次

**如果失败：**
- 提示"token 已过期，请重新登录" → 点 [登录并获取 token] 再来一次
- 提示"厂商接口变更" → 联系 SignDock 维护者提 issue

### 5.4 秒哒（最特殊，有专属登录窗口）

**前置：** 需要一个 [秒哒](https://www.miaoda.com/) 账号。

**配置步骤：**

1. 点击 **秒哒** Tab
2. 模式选 **自动签到**
3. 时间设 **09:00**（或你喜欢的时间）
4. 点 **保存**
5. 点 **[打开登录窗口]** 按钮
6. SignDock 会弹出一个**自己的窗口**（不是浏览器），你在那个窗口里登录秒哒
7. 登录成功后，回到 SignDock 设置窗口，点 **[我登录好了，取会话]**
8. 状态栏显示"会话已封存" → 点 **立即执行一次** 验证

**SignDock 做了什么：**
- 秒哒没有"领取"接口，服务端逻辑是"当日登录一次 → 发放 100 秒点"
- SignDock 用 WebView2 打开一个独立的登录窗口，让你在里面登一次
- 登录成功后 SignDock 读取窗口的 cookie 罐，用服务端验证会话是否有效
- 验证通过后把会话 cookie 用 DPAPI 封存到 `%APPDATA%\com.signdock.app\miaoda-cred.json`
- 之后每天 SignDock 自动用这个会话"访问"一次，触发服务端发放
- **不碰你的浏览器**、不修改你的 chrome/edge 里的任何登录状态

**注意：**
- 免费版**每月最多领 7 天**。领完之后当天没发放属正常，SignDock 会显示"今日已签到，但没有发放到账"
- 如果提示"秒哒登录窗口已经关掉了"，说明窗口被手动关了 → 重新点 [打开登录窗口]

## 6. 三态模式详解

每款产品独立配置一个模式，控制它到底做不做事、做什么事。

| 模式 | 行为 | 系统通知 | 典型场景 |
|---|---|---|---|
| **关闭** | 完全跳过，不参与调度、不发通知 | 无 | 你不想签这个了，但也不想删配置 |
| **仅提醒** | 到点只发通知，不请求签到接口 | "到点了，请手动签到 WorkBuddy" | 想手动签、但要 SignDock 提醒你 |
| **自动签到** | 到点查询状态并自动执行签到 | "WorkBuddy 签到成功 / 失败" | 全自动，不用管 |

### 切换模式的常见理由

- 发现某产品风控了 → 立刻切成 **关闭**
- 想手动签但怕忘 → 切成 **仅提醒**
- 一切正常 → 保持 **自动签到**

## 7. 高级配置

### 7.1 时间抖动（jitter）

SignDock 的触发时间**不是精确到秒**的。每次触发会加 **0~10 分钟的确定性 jitter**（同一个用户在一天内的相对偏移是稳定的，跨天会重新计算）。

**为什么这么做：**
- 避免整个互联网的用户在同一秒同时打到厂商签到接口
- 只往后推，不会拉回窗口外（比如 Qoder 10:00 刷新 → 你设 10:00 也可能真的在 10:03 触发，不会提前）

**你会看到的现象：** 设 09:00，实际可能在 09:00 - 09:10 之间的任意一秒触发。

**能不能关闭 jitter？** 目前不能。这是有意为之的行为，不建议关闭。

### 7.2 补偿重试

配置项：**重试次数** 和 **间隔分钟**，出厂默认 **2 次 / 5 分钟**。

**适用场景：** 网络临时抖动、厂商接口 502、瞬时超时。

**行为细节：**

| 情况 | 重试吗 | 消耗重试次数吗 |
|---|---|---|
| 网络错误（超时、连接重置） | ✅ 是 | ✅ 是 |
| HTTP 502 / 503 / 504 | ✅ 是 | ✅ 是 |
| 今日窗口未开（Qoder） | ✅ 是 | ❌ 否（不消耗，只按间隔复查） |
| token 过期 | ❌ 否 | — |
| 需要人工（比如触发风控） | ❌ 否 | — |
| 厂商接口 401/403 | ❌ 否 | — |

**调优建议：**
- 家里 Wi-Fi 不稳 → 提高到 3-4 次 / 5 分钟
- 出差用 4G/5G → 提高到 3 次 / 10 分钟
- 网络稳 → 保持默认即可
- **不要设 0 次**：那意味着"第一次失败就直接放弃"，等于关掉了重试

### 7.3 积分刷新

**刷新积分** 按钮：手动触发一次积分查询。

**默认行为：** 每次点击 Tab 切换产品，SignDock 会自动加载一次积分。

**积分面板显示什么：**

| 字段 | 含义 |
|---|---|
| 余额 | 账户当前可用积分 |
| 今日消耗 | 今天已用的积分（不管是不是 SignDock 签到的都算） |
| 今日到期 | 今天到 23:59 会失效的积分 |
| 明日过期 | 明天会过期的积分 |
| 查询于 | 数字刷新时间 |

**为什么签到后积分可能没变：** 发放到账是跨服务异步的。WorkBuddy 的签到打在营销服务上，余额读的是 billing 汇总，两个服务同步有延迟。**SignDock 会在签到成功 5 秒后自动重读一次积分**。如果这时候数字还没变，稍等一下再点 [刷新积分]。

## 8. 系统通知与托盘

### 8.1 托盘菜单

右键点击托盘图标：

```
打开设置         → 弹出设置窗口
立即签到（全部） → 立即对所有"自动签到"模式的产品执行签到
退出             → 完全退出 SignDock
```

### 8.2 通知内容

SignDock 发出的通知分几种：

| 通知类型 | 触发时机 | 示例文本 |
|---|---|---|
| ✅ 成功 | 签到成功 | "WorkBuddy 签到成功：+50 积分" |
| ℹ️ 已签 | 已经签过，跳过 | "Trae 今日已签到，没有重复领取" |
| 🔔 提醒 | 仅提醒模式到点 | "到点了，请手动签到 WorkBuddy" |
| ⚠️ 需人工 | 需要手动处理 | "WorkBuddy 签到需要重新登录" |
| ❌ 失败 | 签到失败 | "WorkBuddy 签到失败：token 过期" |
| ⏳ 窗口未开 | Qoder 等滚动窗口 | "Qoder 今日窗口未开，10:00 后再试" |

### 8.3 通知权限

首次运行 SignDock 会请求 Windows **系统通知权限**。如果通知没弹出：

1. Win+I → 系统 → 通知 → 找到 **SignDock** → 打开开关
2. 关闭 **勿扰模式**（Win+N → 找到勿扰 → 关闭）

## 9. 故障排查 FAQ

### 9.1 打开 SignDock 显示"读取配置失败"

**可能原因：**
- 上一次退出时 SignDock 没正常写 SQLite 数据库
- 权限问题（比如把 SignDock 放到了 `C:\Program Files` 下）

**解决：**
1. 退出 SignDock
2. 删掉 `%APPDATA%\com.signdock.app\` 整个目录（这会丢失所有配置和日志）
3. 把 SignDock 移到用户可写目录（如 `D:\SignDock\`）
4. 重新启动

### 9.2 启动后没有托盘图标

**可能原因：**
- Windows 把托盘图标折叠进"隐藏图标"了
- SignDock 进程实际上没起来

**解决：**
1. 点系统托盘右下角的 `^` 箭头展开
2. 或者任务管理器 → 详细信息 → 找 `SignDock.exe` 看进程在不在
3. 进程不在 → 双击 exe 重新启动

### 9.3 WorkBuddy 提示"无法自动读取 accessToken" / "登录失败"

**情况一：报错「WorkBuddy 5.6+ 已加密本机登录凭据，SignDock 读不到你网页登录的 token」**

这是**正常现象**，不是 bug。WorkBuddy 5.6 起把本机登录凭据用厂商密钥加密了，SignDock 无法读取你**网页登录**产生的 token。两者是**两套独立会话，互不相通**——你在 workbuddy.cn 网页上登没登录，SignDock 这边都读不到。

**解决：** 在 WorkBuddy 卡片下方点 **[登录并获取 token]**，用 SignDock 自己的官方登录页授权一次（不需要复制粘贴 token）。登录成功后凭据会用 DPAPI 加密存到 SignDock 自己的文件里，之后自动续期。

**情况二：点完 [登录并获取 token] 后报「登录失败：登录未完成: code=11217 / login ing…」**

这是旧版本的一个 bug：服务端在登录完成的过程中会短暂返回 `code=11217`（意为"登录进行中"），旧代码把它误判成"登录失败"并中断了流程，导致浏览器里明明登录成功了，SignDock 却拿不到 token。

**已修复：** v0.1.1 起该状态会被正确识别为"还没点完、继续轮询"，稍等几秒即可自动完成。如果你用的是旧版绿色版，请升级到最新 release。

**其它"登录失败"原因：**
- 浏览器被防火墙拦了 / OAuth 登录页打不开
- 公司代理拦截了回调地址

**解决：**
1. 点 [重新打开登录页] 再登一次
2. 换系统默认浏览器（edge/chrome）试试
3. 检查是否被代理/防火墙拦截

### 9.4 Trae 签到失败：token 过期

**处理：**
1. 打开 Trae 应用本身，让它自己刷新一次 token
2. 等 30 秒
3. 回到 SignDock 点 [立即执行一次]

**为什么会过期：** Trae 的 refresh_token 是 Trae 客户端自己续期的。SignDock 只读不写，不会主动刷新。所以你只要在电脑上有 Trae 客户端跑着（哪怕后台），Trae 会自动续期，SignDock 下次签到就能用。

### 9.5 Qoder 10:00 后仍显示"窗口未开"

**可能原因：**
- Qoder 客户端本身有问题，或者 Qoder 后端 10:00 后依然没放量
- 网络问题导致复查失败

**解决：**
1. 打开 Qoder 客户端确认今天已经领到过积分
2. 回到 SignDock 点 [刷新积分]，看余额对不对
3. 手动点 [立即执行一次]，看是不是能成功
4. 还不行 → 关掉 Qoder 客户端，重启，再重试

### 9.6 秒哒提示"秒哒还不认这个会话"

**含义：** 你点了 [我登录好了，取会话]，但 SignDock 拿到的会话 cookie 服务端不认。

**解决：**
1. 确认在 SignDock 弹出的登录窗口里**确实登录成功了**（有你的头像、账户名）
2. 关掉登录窗口，重新点 [打开登录窗口] 重来一次
3. 登录成功后再点 [我登录好了，取会话]

### 9.7 免费版 7 天领完就没发放了

**这是产品设计，不是 bug。** 秒哒免费账号每月最多领 7 天。领完之后当天 SignDock 会显示"今日已签到，但没有发放到账"，或者"成功"（因为访问事件成功了，只是没触发发放）。

### 9.8 系统通知完全收不到

1. Win+I → 系统 → 通知 → 通知 → 找到 **SignDock** → 打开
2. 关掉 **勿扰模式**
3. 如果还是不行，检查是不是 **SignDock 被 Windows 判定为"低电量模式不通知"** → 电源 → 电池 → 关掉省电模式

### 9.9 想清空全部历史

1. 退出 SignDock
2. 打开资源管理器，地址栏输入 `%APPDATA%\com.signdock.app`
3. 删除整个目录（这包括所有配置、日志、DPAPI 封存的凭据）
4. 重新启动 SignDock，回到出厂状态

### 9.10 卸载 SignDock

1. 托盘右键 → 退出
2. 删掉 SignDock 目录（如果是绿色版就是解压的那个文件夹）
3. 可选：删掉 `%APPDATA%\com.signdock.app\` 清数据
4. 可选：如果加了开机自启，去 `shell:startup` 删快捷方式

**绿色版无残留：** 不需要跑卸载程序，删完就是删完了。

## 10. 数据安全与卸载

### 10.1 数据都在哪儿

| 数据 | 位置 | 说明 |
|---|---|---|
| 配置文件 | `%APPDATA%\com.signdock.app\` | SQLite 数据库，纯本地 |
| WorkBuddy 凭证 | `%APPDATA%\com.signdock.app\workbuddy-cred.json` | DPAPI 加密 |
| 秒哒会话 | `%APPDATA%\com.signdock.app\miaoda-cred.json` | DPAPI 加密 |
| 签到日志 | 上面的 SQLite 数据库里 | 纯本地 |
| 网络流量 | 只到厂商官网 | 不经过任何第三方 |

### 10.2 DPAPI 是什么，安全吗

DPAPI（Data Protection API）是 Windows 内置的加密机制。**你当前登录的 Windows 用户**能解开，其他用户、其他 Windows 账号、甚至同一台电脑但不同用户登录都解不开。

**含义：**
- 换用户登录 → SignDock 需要重新登录一次
- 换电脑 → 需要重新登录一次（DPAPI 是绑定机器）
- 电脑被重装系统 → 需要重新登录一次

**不加密的东西：** 配置、日志、签到历史都是明文 SQLite，因为没什么敏感的。

### 10.3 卸载干净不留后

**绿色版：**
```
1. 托盘退出
2. 删除解压目录
3. 删除 %APPDATA%\com.signdock.app\
4. 删除启动菜单快捷方式（shell:startup）
```

**完全干净**，不留注册表、不留服务、不留计划任务。

## 11. 已知限制与厂商风险

### 11.1 非公开接口

SignDock 调用的都是厂商**非公开**接口（未文档化、可能随时变）。**厂商随时可能：**
- 更改接口结构
- 封禁某些客户端指纹
- 强制用户验证
- 直接封号

**应对：**
- 如果签到突然大面积失败，先看 [SignDock 的 GitHub Issues](https://github.com/<owner>/signdock/issues) 有没有人报
- 出现风控信号**立即停用**，不要继续重试
- 关注 SignDock 更新日志，通常会第一时间修

### 11.2 免费版发放规则

| 产品 | 免费版额度 | 发放机制 |
|---|---|---|
| WorkBuddy | 每日发放积分 | 到点自动发放 |
| Trae | 每日发放额度 | 到点自动发放 |
| Qoder | 每日 100 秒点 | **北京时间 10:00 刷新** |
| 秒哒 | 每日 100 秒点 | **免费版每月最多 7 天** |

### 11.3 使用场景白名单

✅ **本工具支持：**
- 单用户、单账号、单机
- 每天自动签到一次
- 手动补签、手动刷新积分
- 记录本地签到历史

❌ **本工具不支持（且永不支持）：**
- 多账号切换
- 多开实例（同时开多个 SignDock）
- 批量签到（一次签多台/多个账号）
- 会话复制 / 凭据导出
- 商业运营 / 团队共享

### 11.4 遇到风控怎么办

**症状：** 通知里出现"账户被限制"、"验证失败"、"需要滑块验证"等字样，或者厂商账号登录页突然要求手机验证。

**处理：**
1. **立即停用 SignDock**：把所有产品的模式切成"关闭"
2. **手动登录厂商官网**：观察账号状态是否被风控
3. **不要**手动重试签到，那会加重风控
4. **不要**在 SignDock 的 issue 区报账号被风控，那是敏感信息

如果确实是误判，联系厂商客服申诉。

## 12. 术语表

| 术语 | 含义 |
|---|---|
| **托盘** | 系统任务栏右下角的通知区域（Windows 里通常叫"通知区域"或"系统托盘"） |
| **绿色版** | 免安装的软件形式，解压即用，删除即卸载 |
| **DPAPI** | Windows Data Protection API，本机加密机制，跨账号/跨机器解不开 |
| **OAuth** | Open Authorization，第三方授权登录协议。SignDock 借道系统浏览器跳官方登录页 |
| **access_token** | 短期访问令牌，一般几小时到期 |
| **refresh_token** | 长期刷新令牌，用来换新 access_token |
| **jitter** | 时间抖动。SignDock 在触发时间上加 0-10 分钟的随机偏移，避免全互联网用户同时请求 |
| **补偿重试** | 临时失败后按用户设置再试几次 |
| **WebView2** | 微软的 Chromium 内核 Web 控件，SignDock 用它画设置窗口和秒哒登录窗口 |
| **秒点** | Qoder 和秒哒的免费额度单位（1 秒点 = 1 次请求/对话的额度） |
| **风控** | 厂商风控系统，检测异常行为（比如短时间内大量签到、多账号切换） |
| **Tauri** | Rust 编写的桌面应用框架，SignDock 用它构建 |
| **SQLite** | 轻量级文件数据库，SignDock 存配置和日志 |
| **DPAPI 封存** | SignDock 自造的动词，指用 DPAPI 把敏感数据加密后写盘 |
| **会话封存** | 特指秒哒的登录会话 cookie 被 DPAPI 加密后落盘 |
